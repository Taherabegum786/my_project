# Leighton-Micali Hash-Based Signatures (RFC 8554 2019)
url: https://www.rfc-editor.org/rfc/rfc8554.txt
read: full
problem: Specifies LM-OTS one-time signatures and the LMS Merkle-tree signature (plus HSS) built on hash functions, stated to remain secure against quantum attackers.
method: LMS tree of height h over LM-OTS (Winternitz w) keys; signature = u32str(q) || lmots_signature || u32str(type) || path[0..h-1]; public key = u32str(type) || u32str(otstype) || I (16 B) || T[1] (m B). Stateful: each leaf q used once.
numbers: LM-OTS sig_len (Table 1, SHA-256, n=32): W1 8516 B, W2 4292 B, W4 2180 B, W8 1124 B. Smallest set LMS_SHA256_M32_H5 with LMOTS_SHA256_N32_W8: signature 1292 B and public key 56 B. These two are DERIVED by me from stated field lengths (4+1124+4+5*32; 4+4+16+32), not tabulated in the RFC. LM-OTS signature stated as 4+n*(p+1) B. Table 2 heights h = 5,10,15,20,25 (2^h signatures per key). Keygen cost p*(2^w-1)+1 hashes (LM-OTS).
limits: Stateful (state reuse breaks security); no per-signature size table for full LMS; no benchmarks or broadcast/lossy-channel treatment.
use-for: benchmark, framework
